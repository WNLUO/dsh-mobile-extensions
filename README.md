# DSH 手机扩展：开发者文档与示例

这个仓库是 DSH 手机 App「扩展」功能的第三方开发者入口。写扩展的人从这里拿到说明书和
能跑的样例；维护文档、样例的更新也都发生在这里，不再散落在别处。

- **`docs/extension-authoring.md`**：作者须知。包长什么样、能干什么、怎么跟 App 说话、
  怎么调试，全在这一份。
- **`docs/extension-sample/`**：最小可用样例。一个 `manifest.json` + 一个 `index.html`
  就是「一个扩展」的全部，拷走改字就能起步。

## 这份文档和你装的插件是什么关系

扩展最终是随 `dsh-mobile-plugin` 这个 npm 包发到用户电脑上的，写扩展的人装完插件就能在
本地读到同一份说明书。所以**本仓库是唯一来源**，发布插件版之前由发布流程把 `docs/` 下的
文档与样例同步进插件包、跟着一起发；两边对不上，发版预检会拦下来。换句话说：你在这里看到
的就是插件包里那份，不会出现「照着文档写、插件却是旧接口」的情况。

同步方向只有一个：本仓库 → 插件包。别在插件包里手改这两份文件，下一次同步会覆盖。

## 跑一个样例

样例是一个独立目录，不需要发 npm，用 App 的「本地开发」就能装进手机：

1. 把整个目录拷到电脑的开发目录，目录名就是它的标识：
   `cp -r docs/extension-sample ~/.dsh/extension-dev/example`
2. 手机上：设置 → 扩展 → 打开「开发者模式」→ 回到扩展页 → 最底下「本地开发」→ 刷新 → 导入。
3. 之后改页面里的字，回手机重进这一页就是新的；想自动刷新，见作者须知第 9.1 节。

这是**给你自己边写边看**的调试通道，不适合分发给别人。

## 给别人装：做成插件

扩展是插件带出来的。要让人在手机扩展页里正常安装你的扩展（走安装、逐文件校验、留一版可
回退那条正式路径），得把扩展放进一个插件包：

1. 插件 `package.json` 里声明 `"dshMobileExtensions": "extensions"`（值＝包内相对目录）。
2. 扩展目录放在包内那个位置，比如 `extensions/<名字>/`。
3. 用户按正常方式装这个插件，他的手机连上电脑后，扩展页里就会出现你带的扩展。

`plugin/` 目录就是一个能直接装的完整样板，带的正是下面那三个 demo。要取电脑上的数据，
还得在插件 `package.json` 里加 `dshMobileDataServices`，见作者须知第 5.5 节。

## 目录

```

```
